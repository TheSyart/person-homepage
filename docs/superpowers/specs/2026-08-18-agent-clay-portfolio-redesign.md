# 小单说 AI：Agent Clay 作品集重构设计规格

日期：2026-08-18
状态：已批准
范围：公开站点前端、公开内容数据、CSDN 已发布文章迁移
不在范围：管理后台重构、公开 API 地址或响应结构变更、生产部署方式变更

## 1. 背景与问题

现有 Clay 版本虽然统一了色板和组件外观，但首页同时承载 GitHub、视频账号、文章、完整个人介绍、22 项技能、10 张校园照片、5 项兴趣、4 个外部平台和 3 种联系方式，导致首屏之后缺少明确叙事主线。个人定位仍以“计算机专业本科生 / Java 与 Vue 全栈开发”为中心，也与当前 GitHub 项目和视频内容所体现的 Agent 方向不一致。

现有抖音粉丝数不是实时事实。`SNAPSHOT.douyin.followers` 与 `public/data/stats.json` 都将其写死为 `2000`，而 `useStats` 没有抖音实时请求链路；页面却把这一数值连同更新时间一起展示，容易被理解为已验证统计。

用户 CSDN 创作中心当前显示 34 篇已发布文章和 3 篇草稿。个人站目前的 2 篇本地 Markdown 是占位内容，必须由真实 CSDN 文章全量替换。

## 2. 设计目标

1. 将首页变成强叙事、低冗余的入口，而不是完整资料汇总页。
2. 以“开源 Agent 构建者与 Agent 内容创作者”作为第一身份。
3. 使用已确认的全屏动态 Clay Hero，在进入页面第一秒建立视觉记忆。
4. 所有既有事实、资料、图片、技能、链接和功能继续可访问，只允许迁移到更合适的页面，不允许删除或隐藏。
5. 抖音只展示有来源、可解释的事实；无法可靠获取的统计不展示精确值。
6. 将 CSDN 的 34 篇已发布文章完整迁移为站内可阅读的本地文章，并删除当前 2 篇占位文章；3 篇草稿不自动公开。
7. 不破坏现有路由、API、留言逻辑、文章管理逻辑和数据兜底能力。

## 3. 事实依据与新定位

新定位只使用能够由公开项目或公开内容确认的事实：

- `claude-agent-examples` 是“从零实现 Agent”的递进式教学项目，覆盖模型调用、循环、上下文、工具、Skills、记忆、任务规划、子代理、Agent Team、MCP 与 Hooks 等 12 个阶段。
- `emperor-agent` 是面向个人长期使用的本地 Agent 工作空间，包含多模型、工具、记忆、规划、子代理、调度与长任务等方向。
- B站已形成至少 9 集 Agent 专题内容，主题与上述项目对应。
- GitHub Star、Fork、关注者和 B站粉丝继续使用既有实时请求与快照兜底；易变化的数值不得写进固定文案。

### 3.1 首页主文案

主标题：

> 把 AI Agent 做活。

核心介绍：

> 我把 Agent 的关键零件拆开、讲透、重新组装——从百行代码到能规划、记忆、协作和长期工作的个人智能体。

首要行动：`进入 Agent 实验室`，指向 `/agents`。
次要行动：`观看系列视频`，指向 `/videos`。

### 3.2 关于我正文

`ABOUT_PARAS` 保持三段导出结构，但内容替换为：

1. `我是小单，一个把 AI Agent 做成开源项目，也把实现过程讲给别人听的创作者。比起停留在模型演示，我更关心 Agent 怎样调用工具、保留记忆、规划任务，并把一件事真正做完。`
2. `从模型调用、工具与 Skills，到记忆、任务规划、子代理、Agent Team、MCP 和 Hooks，我正在用代码、视频和真实项目搭建一条可以复现的 Agent 学习路线。claude-agent-examples 负责把原理逐步拆开，emperor-agent 则尝试把这些能力装进一个可以长期使用的个人工作空间。`
3. `我也持续体验 Claude、Codex、DeepSeek、Kimi 等 AI 编程工具。关注的不是简单的模型排行榜，而是它们能否进入真实开发流程、稳定完成任务，并逐渐成为可以长期协作的个人 Agent。校园经历、传统开发技能和兴趣仍是我的背景，但不再占据首页的中心位置。`

### 3.3 配置文本调整

- `PROFILE.roles` 改为：`Agent 开源作者`、`AI 内容创作者`、`Agent 实践者`、`教程作者`。
- `PROFILE.identity` 改为：`AI Agent 开源作者 / 内容创作者`。
- `PROFILE.tagline` 使用首页核心介绍。
- 学校、生日、兴趣、邮箱、微信、所有平台链接与账号信息原样保留。
- 22 项既有技能原样保留，并在页面上定义为“构建 Agent 的工程底座”，不把它们伪装成新的 Agent 专项技能。

## 4. 信息架构

### 4.1 路由

保留所有现有公开路由：

- `/`
- `/articles`
- `/articles/:slug`
- `/videos`
- `/messages`
- 404 捕获路由

新增：

- `/agents`：Agent 项目、学习路线、仓库与工程技能
- `/about`：个人资料、完整介绍、校园、兴趣、平台与联系

导航顺序：`首页 / Agents / 文章 / 视频 / 关于 / 留言 / GitHub`。移动端允许两行，但不得隐藏任何入口，触控目标不小于 44px。

### 4.2 首页内容边界

首页只保留五个叙事单元：

1. 全屏动态 Clay Hero。
2. 四项能力证明：`claude-agent-examples` 实时 Star、`emperor-agent` 实时 Star、12 阶段 Agent 路线、9+ 集 Agent 内容。
3. 两个核心 Agent 项目卡，分别链接到项目详情区或 GitHub。
4. 最新内容：最多 2 篇文章与 2 条视频，使用一条紧凑内容轨道，不再使用两个大型面板。
5. 前往 `/agents`、`/about`、`/articles`、`/videos` 的结尾导航与全站页脚。

首页移除完整 GitHub 账号面板、完整视频账号面板、AboutFull、技能墙、校园相册、兴趣卡、平台卡和联系方式。这些内容不是删除，而是迁移到 `/agents`、`/videos` 与 `/about`。

### 4.3 Agents 页面

页面叙事顺序：

1. Agent 定位引言与实时 GitHub 账号资料。
2. 12 阶段学习路线，按“基础循环 → 工具与能力 → 记忆与规划 → 多代理协作 → 协议与控制”分组显示。
3. `claude-agent-examples` 和 `emperor-agent` 两个主项目的强化展示。
4. 其余 6 个仓库全部展示，保持原链接、语言与 Star 数据。
5. 22 项既有技能完整展示，标题为“工程底座”，按后端、前端、移动端、数据与基础设施、创作工具分组；不改变 `SKILLS` 导出结构。

### 4.4 About 页面

页面完整容纳：

- 4 项个人信息：博主名、生日、学校、身份。
- 新的三段关于我正文。
- 10 张校园照片。
- 5 项兴趣爱好。
- 快手、CSDN、掘金、知乎四个平台。
- 邮箱、微信、GitHub 三种联系方式。
- B站与抖音账号简介和外部链接；粉丝统计由各自的事实规则控制。

### 4.5 视频页面

保留所有现有视频及后续 API 数据、平台、日期、标题、描述、链接、加载与空状态。页面顶部增加“Agent 系列”说明和 B站账号资料。抖音作为内容分发渠道展示账号名、抖音号和链接，不展示未经验证的精确粉丝数。

### 4.6 文章、留言与 404

- 文章列表、文章详情、留言、404 保留现有功能与 Clay 视觉，只根据新的导航、内容规模与无障碍要求做必要调整。
- 文章列表在 34 篇规模下采用响应式网格；后端继续一次返回完整列表，不新增 API 分页。
- 文章正文继续使用当前 Markdown 渲染链路。
- 留言提交、蜜罐、限流、分页、成功/失败状态完全不改业务逻辑。

## 5. Hero 视觉与动态设计

采用已经确认的 `Clay Motion V3` 方向，不使用玻璃拟态或霓虹科技面板作为主视觉。

### 5.1 构图

- 首屏最小高度为 `100svh`，桌面端左文案、右软体 Agent 核心；移动端上下排列。
- 主标题使用超大两行排版：`把 AI / AGENT 做活。`，避免在桌面端拆成意外的第三行。
- 右侧核心使用真实 GitHub 头像作为中心，四周围绕 Star、Memory、Agent Team、12 Steps 等粘土标签。
- 背景延续 `#f6f1ff` 与蓝、粉、绿、黄四组柔和径向色块。

### 5.2 材质动效

动效必须来自粘土材质本身，而不是只给元素增加位移：

- 核心持续改变不对称圆角，形成软体呼吸。
- 入场采用压扁、拉伸、回弹的 squash-and-stretch。
- 点击或键盘激活核心时先下压、横向变宽，再纵向回弹，并释放 12–18 个彩色软颗粒。
- 标签以不同周期轻微变形、摆动和上下漂浮，禁止所有元素使用相同节奏。
- 高光、外浮阴影、顶部内高光和底部内阴影随组件形变保持一致的光源方向。
- 鼠标或触控位置只产生轻量分层视差；最大移动距离受限，不能影响文字可读性。
- Clay 按钮在 hover 时轻抬升，在 active 时真正压入并缩短阴影。

### 5.3 动效约束

- 交互动效使用 transform、opacity 与 border-radius，避免持续触发布局。
- 粒子只在用户激活时短暂创建，动画结束后从 DOM 删除。
- `prefers-reduced-motion: reduce` 下停止持续漂浮、粒子、视差和打字动画；保留静态构图与即时状态反馈。
- 动画不能阻塞导航、文本选择、键盘操作或首屏内容读取。

## 6. 抖音事实修复

### 6.1 立即删除的错误表达

- 将 `SNAPSHOT.douyin` 与 `public/data/stats.json` 中未经核验的 `followers/likes/works` 数值设为 `null`，保留既有字段结构，但不再用旧数值冒充事实。
- 删除“抖音粉丝 · 某日期更新”这类暗示已经核验的文案。
- 不再把抖音静态数据与 GitHub/B站实时状态放在同一种计数 UI 中。

### 6.2 允许展示的事实

- 品牌名：小单说 AI。
- 抖音号：`23329202234`。
- 现有抖音主页链接。
- 已写入视频数据且有真实链接的视频条目。

### 6.3 数据模型原则

`useStats` 的 GitHub 与 B站兜底链保持不变。抖音改为可空状态：没有可靠获取结果时只显示账号身份，不显示 `0`、估算值或旧快照。若未来接入稳定数据源，必须同时记录 `verifiedAt` 或在 UI 中明确实际获取时间；本轮不新增抖音抓取依赖。

## 7. CSDN 文章迁移

### 7.1 范围

- 从用户已登录的 CSDN 内容管理后台遍历 2 页文章列表。
- 导入当前 34 篇“已发布”文章。
- 3 篇草稿不导入为公开文章；除非用户以后明确要求，否则不改变草稿发布状态。
- 当前 `hello-new-home.md` 与 `why-all-in-ai.md` 是占位内容。34 篇真实文章全部通过完整性验证后删除这两个文件，迁移后公开文章总数必须为 34。

### 7.2 每篇文章的迁移规则

1. 从后台或公开文章页获取真实标题、发布日期、正文、标签和原文 URL。
2. 优先读取编辑器中的原始 Markdown；若原文为富文本，则转换为语义等价 Markdown，保留标题层级、段落、引用、列表、代码块、表格、链接和图片。
3. Slug 使用 `csdn-<文章数字 ID>`，避免中文标题变化造成链接不稳定，并满足现有 80 字符校验。
4. 摘要从正文第一个有效文本段截取，不杜撰新结论。
5. 图片下载到 `public/articles/csdn/<文章 ID>/`，文件名去除查询参数并处理重名；正文链接改为站内绝对路径。
6. 文末添加简短来源行：`原文发布于 CSDN`，链接到真实公开地址。
7. 文件写入 `api/data/articles/*.md`，继续使用现有 frontmatter 字段：`title/date/summary/tags/draft`；不修改公开 API 数据格式。

### 7.3 完整性与幂等性

- 以 CSDN 文章 ID 去重；重复执行不会生成第二份文章。
- 每篇文章写入后验证：文件非空、标题一致、正文长度合理、代码围栏成对、图片路径存在、公开 URL 可追溯。
- 迁移结束输出清单：后台文章 ID、标题、日期、本地 slug、图片数和导入状态。
- 若单篇抓取失败，继续处理其余文章，并在最终清单中单独列出失败原因；不得用空壳文章凑数。

## 9. 响应式、无障碍与视觉质量

- 1440px 桌面：Hero 左右分栏，标题两行，核心不遮挡文字。
- 768px 平板：Hero 保持上下或紧凑双栏，项目与内容使用双栏。
- 390px 手机：全部内容单栏，不出现横向滚动；标题按设计断行，CTA 不得被裁切，动态核心完整进入视口。
- 使用真实 `ul/li/a` 语义，禁止给链接覆盖 `role="listitem"`。
- Markdown 正文恢复 `ul` 的圆点与 `ol` 的数字标记，保留嵌套缩进。
- 小号正文使用对比度至少 4.5:1 的深色文本 token；参考色 `#8a7aa0` 只用于满足对比度的大号或装饰文字。
- `focus-visible` 使用深色外环加浅色间隔环，在白、蓝、粉、绿、黄表面均达到至少 3:1 的可见边界。
- 所有图像具有对应语义的 alt；纯装饰粒子隐藏于辅助技术。
- 所有可点击目标最小 44×44px，键盘可到达 Hero 核心、导航、卡片和分页。

## 10. 错误与空状态

- GitHub/B站实时请求失败：继续显示有日期的快照，并只在成功实时获取时显示 live 标志。
- 抖音无可靠数据：显示账号卡，不显示数字占位符。
- 首页文章或视频 API 失败：对应紧凑轨道显示独立空状态，不影响 Hero 与静态内容。
- 头像加载失败：继续使用“小单”印章兜底。
- CSDN 单篇迁移失败：记录并报告，不生成不完整文章。
- 文章图片缺失：保留原始远程链接作为临时兜底，并在迁移报告中标记，不能静默丢图。

## 11. 验收标准

### 11.1 内容

- 首页不再展示完整个人档案墙，首屏明确聚焦 Agent。
- 2 个主项目、6 个其他仓库、22 项技能、4 项个人信息、3 段新介绍、10 张校园照片、5 项兴趣、4 个更多平台和 3 种联系方式均能从新增页面访问。
- 所有现有视频继续可访问。
- 34 篇 CSDN 已发布文章全部成为站内 Markdown 文章；当前 2 篇占位文章不再存在，公开文章总数必须为 34。
- 任何页面都不再显示无来源的抖音粉丝精确值。

### 11.2 视觉与交互

- Hero 与 Clay Motion V3 原型保持同一构图和软体动效语言。
- 桌面、平板、手机均无横向溢出或内容裁切。
- 点击与键盘激活核心均能获得粘土挤压反馈；减少动态设置下不播放持续动画。
- 导航、正文、卡片、焦点、列表语义满足上述无障碍约束。

### 11.3 工程验证

- `npm test` 全部通过。
- `npm run build` 零编译错误。
- 在 1440×1000、768×1024、390×844 下逐页验证 `/`、`/agents`、`/about`、`/articles`、至少 3 篇文章详情、`/videos`、`/messages` 与 404。
- 浏览器控制台无项目代码产生的错误或警告。
- 不修改 `/api/articles`、`/api/videos`、`/api/messages` 与管理端接口格式。

## 12. 实施顺序与风险控制

1. 先为新路由、首页内容边界、抖音可空状态和 Markdown 列表语义增加失败测试。
2. 重构配置文案、路由、导航与页面归属。
3. 将获批 Hero 原型移植为 Vue/CSS，随后做三视口调校和减少动态支持。
4. 修复抖音静态假数据及所有依赖 UI。
5. 使用已登录浏览器逐篇迁移 CSDN 文章与图片，生成核对清单。
6. 运行单元测试、生产构建、控制台检查和全路由视觉验收。

主要风险是 CSDN 编辑器可能混用 Markdown 与富文本、图片地址可能带鉴权或防盗链。处理原则是逐篇验证、优先保存原始语义、图片失败时保留可追溯链接并显式报告，绝不生成看似成功但正文或图片缺失的文章。
